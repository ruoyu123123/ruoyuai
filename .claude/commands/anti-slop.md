# Anti-Slop 机械扫描规则库

本文件定义了不依赖LLM的机械检测规则，用于在写作后自动扫描AI腔调痕迹。

---

## 🔗 与语义层的分工（v19 · 必读）

Anti-Slop 是**机械层**——正则抓「词」和「字频」，零 LLM 成本，快、准、噪音低。
但句级 / 段级的「语义型 AI 腔」（要理解结构才能判的），正则抓不到。

v19 起，由独立扫描器 **`core/scripts/semantic_slop_scanner.py`（语义层）** 补这块：

| 层 | 抓什么 | 实现 | 举例 |
|----|--------|------|------|
| **机械层**（本文件） | 词 / 字频 / 统计异常 | 正则 + 统计 | 禁用词、"说道"≥5次、对冲词 200 字内≥3次 |
| **语义层**（semantic_slop_scanner） | 句级结构性 AI 腔 | 8 检测器 | 隐喻后紧跟解释、金句体、否定式排比、系动词回避、虚假范围、限定词单句叠用、强行三段列举、对话标签同义词循环 |

**两层互补不重叠**——看着像撞的其实是不同粒度/角度：
- 本文件第五类「对冲词集中度」= 200 字窗口词频；语义层 `over_hedge` = 单句内叠 ≥2 个限定词（不同粒度）。
- 本文件第十类「意味着/象征着 单章≥5次」= 纯词频；语义层 `metaphor_explain` = 「比喻紧跟解释」的句级结构（不同角度）。
- 本文件第三类「说道≥5次」= 单一词重复；语义层 `tag_synonym_cycle` = 标签变体≥6种的同义词循环（正反两面）。

**关键差异**：本文件的判定是「扣分」式硬规则；语义层输出全部 `gate_level=advisory`（v19 顾问制），写作 agent 有充分理由可豁免。语义层已由 `audit_hub.py` 作为第 7 个校验器统一调度。

## 第一类：禁用词检测（Word-Level）

### 通用AI禁用词（出现即扣分）
```
顿时|紧锁|显然|似乎|此刻|淡淡|心中一凛|眼中闪过一丝|微微挑眉
仿佛|嘴角勾起一抹|深吸一口气|缓缓地说|沉吟片刻|不容置疑|波涛汹涌
与此同时|值得一提的是|不仅如此|事实上|不言而喻|毋庸置疑
```

### AI高频过渡词（单章出现≥3次扣分）
```
然而|不过|但是|虽然|尽管|即便|纵然
```

### AI情绪套话（出现即扣分）

```
微微一笑|微微点头|微微皱眉|微微摇头
```

## 第二类：句式均匀度检测（Sentence-Level）

AI生成的文本有一个显著特征：句子长度过于均匀。

**检测方法：**
```
将全文按句号/问号/感叹号分句
计算每连续5句的长度标准差
如标准差 < 3字 → 标记为"AI均匀句式嫌疑"
```

**正常人类写作：** 句长标准差通常 > 8
**AI生成特征：** 句长标准差通常 < 5

## 第三类：结构模式检测（Pattern-Level）

### 段落开头重复模式
```
连续3段以相同词性开头（如连续3段都以"他"开头）→ 扣分
连续3段长度差异 < 10字 → AI嫌疑
```

### 对话标签重复
```
同一页面内"说道"出现 ≥ 5次 → 扣分
同一页面内"笑道/怒道/叹道"出现 ≥ 3次 → 扣分
```

### 三段式套路
```
[环境描写1段] + [角色动作1段] + [对话1段] 循环超过3次 → AI结构嫌疑
```

## 第五类：统计异常检测（v16 新增 · 移植自 AI_NovelGenerator）

**零LLM成本，纯统计/正则检测，捕获AI文本的隐性特征：**

### 段落均匀度系数
```
计算所有段落字数的变异系数 CV = std / mean
CV < 0.15 → 🔴 AI嫌疑（人类段落长短差异大，CV通常>0.3）
CV 0.15-0.25 → 🟡 警告
CV > 0.25 → 正常
```

### 连续句尾"了"检测
```
连续4句以上以"了"结尾 → 🔴 AI标记
连续3句 → 🟡 警告
```
AI生成中文时倾向于用"了"收束每个动作句，人类作者会混用"着/过/省略"。

### 分析术语入侵
```
正文中出现以下词汇（应只在评论/分析中出现，不应出现在小说正文中）：
核心动机|信息边界|叙事张力|人物弧光|内在冲突|外在冲突|角色成长|情感共鸣|
主题表达|象征意义|节奏把控|戏剧冲突|伏笔回收|情感铺垫|价值观输出
出现任何一个 → 🔴 AI分析腔入侵
```

### 对冲词集中度
```
"似乎/可能/或许/大概/也许/仿佛" 在连续200字内出现3次以上 → 🟡 AI模糊表达
```
AI对不确定的内容喜欢堆叠对冲词，人类作者要么确定地写，要么用具体动作表达不确定。

### 公式化过渡词重复
```
"然而/不过/但是" 在单章出现5次以上 → 🟡 AI过渡词依赖
"与此同时/在此期间/就在这时" 在单章出现2次以上 → 🔴 AI时间连接词
```

### 连续段首重复检测（升级版）
```
连续3段以相同2字开头 → 🟡
连续4段以相同2字开头 → 🔴
特别检测"他/她+动词"式AI标准开头：
  连续3段都是"他xxx"或"她xxx"开头 → 🔴
```

### 情绪词密度异常
```
"震惊/惊讶/愤怒/悲伤/喜悦/恐惧" 等直接情绪词
在1000字内出现5次以上 → 🔴 AI情绪堆砌
（人类作者用动作外显情绪，不直接写情绪词）
```

## 第六类：对白工艺检测（v16 新增 · 移植自外部工艺库 prose_craft）

### 对白无动作节拍
```
连续3句以上纯对话（引号行），中间无任何动作描写（按/敲/拽/推/转身/偏头/咬牙/停顿等）
→ 🟡 对白缺少动作节拍（像信息交换不像人说话）
```
动作节拍关键词：抬/按/握/捏/攥/抓/敲/推/拉/扯/摔/塞/转身/后退/偏头/点头/摇头/皱眉/咬牙/停顿/沉默/目光

### 长台词独白
```
单段引号内文字超过80字 → 🟡 疑似信息投喂式独白
应拆成2-4次来回问答，混入回避/反问/转移话题
```

### 章末钩子具体度（移植自外部工艺库 因果转换引擎）
```
章末最后3段检查：
如果章末是总结/感慨式收束（"一切都将改变""从此以后"等）→ 🔴 空钩子
好的钩子需要至少2项：角色(actor) + 目标(objective) / 截止(deadline) / 筹码(stake)
```

## 第九类：脚手架文本残留检测（v16 新增 · 移植自 AI_NovelGenerator narrative_quality_checker）

AI生成时可能残留的"创作笔记"——不应出现在正文中：


## 第十类：说明文入侵检测（v16 新增）

正文中不应出现大段设定解释式文字：

```
# 说明文关键词密度检测
"设定/背景/体系/规则/历史/传说/资料/说明/介绍/解释" 
在连续200字内出现3次以上 → 🟡 说明文入侵（应通过对话/行动展示设定，不直接解释）
"意味着/代表着/象征着/体现了" 在单章出现5次以上 → 🟡 分析腔入侵
```

## 第十一类：MRU反应顺序违规检测（v16 新增 · 基于Dwight Swain理论）

AI常犯的动机-反应顺序错误——角色先说话/行动再有感觉，不符合人类认知顺序：

```
# 正确顺序：感觉→本能动作→理性反应→对话
✅ 一阵冷风吹过（感觉）。她缩了缩肩膀（本能动作），往后退了一步（理性反应）。"谁在那里？"（对话）

# AI常见错误：对话先于感觉
❌ "谁在那里？"她喊道。然后她感觉到一阵冷风。
检测：对话引号后紧跟"感觉/感到/察觉/意识到" → 🟡 MRU顺序疑似颠倒
```

```
# 检测模式（正则）
[""」][^""」]*(?:感觉|感到|察觉到|意识到|发现|听到|看到|闻到)
→ 如果对话结束后才出现感官动词 → 🟡 MRU顺序可能颠倒
```

## 第十二类：与AI默认输出的对比维度

AI默认输出的特征（蒸馏时应标注"作者与AI的差异"）：

| 维度 | AI默认 | 优秀人类作者 |
|------|--------|-------------|
| 句长 | 均匀（15-20字） | 波动大（5-50字） |
| 段落 | 均匀（3-5句） | 变化大（1-15句） |
| 过渡 | 显式连接词 | 场景切换/留白 |
| 情绪 | 直接描述 | 动作暗示 |
| 对话标签 | "说道"为主 | 动作代替/无标签 |
| 开头 | 环境描写 | 冲突/动作/对话 |
| 结尾 | 总结感悟 | 悬念/动作定格 |

## 使用方式

### 在 save-state 第7.5步中调用
```bash
# 快速扫描脚本（Bash执行）
FILE="$1"

echo "=== Anti-Slop Scan ==="

# 禁用词
echo "--- 禁用词 ---"
grep -onE '顿时|紧锁|显然|似乎|此刻|淡淡|心中一凛|眼中闪过一丝|微微挑眉|仿佛|嘴角勾起一抹|深吸一口气|缓缓地说|沉吟片刻|不容置疑|波涛汹涌|与此同时|值得一提的是|不仅如此|事实上' "$FILE"

# AI情绪套话
echo "--- 情绪套话 ---"
grep -onE '心中一暖|心头一震|心中暗道|不由得|嘴角微微上扬|眉头微皱|眼神中闪过' "$FILE"

# AI动作套话
echo "--- 动作套话 ---"
grep -onE '轻轻地|缓缓地|默默地|静静地|淡淡地|微微一笑|微微点头|微微皱眉|微微摇头' "$FILE"

# 对话标签重复
echo "--- 对话标签 ---"
grep -oE '说道|笑道|怒道|叹道|喊道|问道' "$FILE" | sort | uniq -c | sort -rn

# Show-Don't-Tell违规
echo "--- 直接情绪 ---"
grep -onE '感到愤怒|感到悲伤|感到高兴|感到恐惧|内心充满|心中涌起|一股.*涌上心头' "$FILE"

echo "=== Scan Complete ==="
```

### 在 check-quality 中调用
作为质量检查的第一步（机械层），在LLM评估之前执行。

### 在蒸馏时使用
蒸馏子代理的"反模式检测"维度应参考本文件的分类，标注作者是否使用了这些AI常见模式。

---

## 判定标准

| 级别 | 条件 | 处理 |
|------|------|------|
| 🔴 SLOP | 禁用词 ≥ 3个 或 情绪套话 ≥ 2个 | 必须修正 |
| 🟡 WARN | 禁用词 1-2个 或 句式均匀度过高 | 警告+记录 |
| 🟢 CLEAN | 无检出 | 静默通过 |

---

## 维护规则

- 用户反馈"这个词其实可以用"时，从禁用列表移除
- 发现新的AI腔调特征时，追加到对应类别
- 如蒸馏的作者风格中包含某些"禁用词"（作者本人就这么写），则该词对该项目豁免
