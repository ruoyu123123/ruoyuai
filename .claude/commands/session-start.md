# 会话恢复流程

## 第一步：加载项目数据库

依次 Read 以下文件（如存在）：

1. `_数据库/进度.json` — 当前写到第几章、总章数
2. `_数据库/人物卡.json` — 所有角色的设定和状态
3. `_数据库/世界观.json` — 核心设定和规则
4. `_数据库/故事块摘要.json` — 已完成章节的摘要
5. `_数据库/伏笔表.json` — 伏笔埋设和回收状态

如某个文件不存在，跳过并标记为"未初始化"。

---

## 第二步：状态摘要

加载完成后，输出结构化摘要：

```
📚 项目状态恢复完成

进度：第 X/Y 章已完成
总字数：约 Z 万字
主要角色：[角色列表及当前状态]
待回收伏笔：[到期或即将到期的伏笔]
下一章：第 N 章 — [大纲摘要]
```

---

## 第二步半：情感上下文恢复

从 `_数据库/故事块摘要.json` 的最后一条摘要中提取情感上下文：

```
🎭 情感上下文（上次写作结束时的状态）：

主角情绪：[最后一章结束时的情绪状态]
叙事张力：[1-10 分]
未释放的情绪：[角色间未解决的情感冲突]
读者期待：[读者此刻最期待看到什么]
```

这些信息帮助续写时保持情感连贯——避免"上一章主角还在愤怒，下一章突然开心"的割裂感。

如故事块摘要为空（首次写作），跳过此步骤。

---

## 第三步：写前检查

1. **伏笔到期检查**：
   - 遍历伏笔表，找出 `due_by <= 当前章节` 且 `resolved == false` 的伏笔
   - 列出需要在接下来章节中回收的伏笔

2. **角色一致性检查**：
   - 确认主要出场角色的声音包（说话节奏、禁用口头禅）
   - 确认角色当前状态（情绪、处境、目标）

3. **节奏定位**：
   - 根据进度判断当前处于哪个节奏区间：
     - 前30%：虐点密集区
     - 30-50%：转折觉醒区
     - 50-80%：实践成长区
     - 最后20%：升华爽点区

---

## 第四步：准备续写

状态恢复完成后，等待用户指令：
- 用户说"继续写" → 从当前进度继续执行 /write-chapter
- 用户说"检查质量" → 对最近章节执行 /check-quality
- 用户说"修改大纲" → 调整后续章节规划

---

## 异常处理

- 如果 `_数据库/` 目录不存在：提示用户先执行 /outline 生成大纲并初始化数据库
- 如果进度文件损坏：尝试从已有的 txt 文件推断进度
- 如果人物卡缺失：从已有章节中提取角色信息重建
