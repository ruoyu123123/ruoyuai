# 群戏引擎

## 设计哲学

借鉴 SillyTavern Group Chat 的多角色对话系统：
- 每个角色根据自己的性格、目标、关系独立决定说什么
- 不是所有人都围着主角转——配角之间也有互动
- 对话有"轮次"概念——谁先说、谁接话、谁沉默，都有逻辑

## 触发条件

当一个场景中有 3 个及以上角色同时在场时，自动启用群戏模式。

## 对话编排规则

### 发言顺序决定

根据以下因素决定谁先说话：
1. **性格外向度**：外向角色更容易先开口
2. **当前情绪强度**：情绪激动的角色更容易插话
3. **与话题的相关度**：话题与谁最相关，谁更可能发言
4. **关系张力**：与在场某人有冲突的角色更容易被激发
5. **角色目标**：有明确目标要达成的角色会主动发言

### 沉默也是表达

不是每个在场角色都必须说话：
- 内向角色可以只有动作/表情反应
- 旁观者可以只是"观察"
- 沉默本身可以传递信息（"他一直没说话"）

### 对话交叉

允许：
- A 说话时 B 打断
- C 对 A 说的话做出反应，但对着 B 说
- 多人同时说话（用动作描写区分）
- 一个人的话引发连锁反应

### 群戏节奏

- 开头：建立场景，明确谁在场
- 中段：核心冲突/信息交换，2-3 组对话交叉
- 结尾：一个决定性的发言或动作，改变局面

## 写作集成

当 write-chapter 检测到本章有 3+ 角色同时在场时：
1. 从人物卡中加载所有在场角色的性格、目标、关系
2. 在 Agent 子任务 prompt 中注入群戏规则：
   ```
   🎭 群戏模式（本场景 3+ 角色在场）：
   在场角色：[列表及其当前情绪/目标]
   关系张力：[谁和谁有冲突]
   规则：
   - 每个角色独立发言，不围着主角转
   - 配角之间也要有互动
   - 允许打断、插话、沉默
   - 对话推进要有"轮次感"
   ```

## 操作

- `/ensemble [场景描述]` — 为指定场景生成群戏对话
- `/ensemble 分析 [章节]` — 分析某章的群戏质量

---

**目标：让多人场景有"现场感"——不是一对一轮流说话，而是真实的群体互动**
