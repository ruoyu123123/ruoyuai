# 角色关系系统

## 数据结构

`_数据库/关系.json` 格式：

```json
{
  "relationships": [
    {
      "from": "主角",
      "to": "王经理",
      "affinity": -20,
      "trust": 10,
      "fear": 30,
      "respect": 40,
      "history": [
        {"ch": 1, "event": "被当众批评", "changes": {"affinity": -15, "fear": +20}},
        {"ch": 3, "event": "暗中帮助", "changes": {"trust": +10, "respect": +15}}
      ]
    }
  ],
  "faction_standings": {
    "主角": {"青云宗": 50, "万妖山": -30},
    "王经理": {"青云宗": 80, "万妖山": 0}
  }
}
```

## 关系维度

| 维度 | 范围 | 含义 |
|------|------|------|
| affinity | -100~+100 | 好感度（喜欢/讨厌） |
| trust | -100~+100 | 信任度（信任/怀疑） |
| fear | 0~100 | 恐惧度（畏惧程度） |
| respect | -100~+100 | 尊重度（尊重/轻视） |

## 关系变化规则

行为对关系的影响（参考值，可根据情境调整）：

| 行为 | affinity | trust | fear | respect |
|------|----------|-------|------|---------|
| 帮助/救命 | +15~+30 | +10~+20 | -5 | +10 |
| 欺骗/背叛 | -20~-40 | -30~-50 | 0 | -20 |
| 威胁/恐吓 | -10~-20 | -10 | +20~+40 | -10 |
| 展现实力 | 0 | 0 | +10 | +20~+30 |
| 示弱/求助 | +5 | +5 | -10 | -10 |
| 共同经历危险 | +10~+20 | +15~+25 | 0 | +10 |
| 公开羞辱 | -30~-50 | -20 | +10 | -30 |

## 关系对剧情的影响

- **affinity > 60**：角色会主动帮助、分享秘密
- **affinity < -40**：角色会暗中使绊、拒绝合作
- **trust > 70**：角色会相信主角的话、托付重要事物
- **trust < -30**：角色会怀疑主角的一切行为
- **fear > 60**：角色会服从但暗中积怨
- **respect > 70**：角色会认真对待主角的意见

## 阵营连锁反应（v16 新增 · 移植自游戏声望系统）

**核心规则：一个角色的阵营好感变化 → 关联阵营/角色自动连锁调整。**

```json
{
  "faction_relations": {
    "青云宗_vs_万妖山": {"stance": "hostile", "modifier": -0.5},
    "青云宗_vs_天道盟": {"stance": "allied", "modifier": 0.3}
  }
}
```

**连锁规则：**
- 主角对「青云宗」好感+20 → 「天道盟」好感自动+6（20×0.3）/ 「万妖山」好感自动-10（20×-0.5）
- modifier范围：-1.0（死敌）到 +1.0（同盟），0=无关联
- 连锁只传播一层，不二次传播（防止无限连锁）

**在save_state中执行：**
当CHANGES.faction_changes或character_changes涉及阵营好感变化时，自动计算连锁影响并写入关系.json。

## 引用计数追踪（v16 新增 · 移植自Ink引擎访问计数）

**追踪每个设定/地点/角色在正文中被引用的次数，识别"被遗忘的设定"。**

在 `_数据库/关系.json` 新增 `reference_counts` 字段：
```json
{
  "reference_counts": {
    "characters": {"许遥": {"total": 45, "last_ch": 3}, "秦玥": {"total": 12, "last_ch": 2}},
    "locations": {"调度中心": {"total": 8, "last_ch": 3}, "94号线": {"total": 0, "last_ch": 0}},
    "items": {"保温杯": {"total": 5, "last_ch": 2}, "铜钱": {"total": 3, "last_ch": 3}}
  }
}
```

**用途：**
- 每章save-state时自动扫描正文统计引用次数
- 连续5章未被引用的设定/角色 → audit_consistency标记为"被遗忘"
- build_manifest注入时优先关注"即将被遗忘"的元素

## 写作集成

- save-state 中自动更新关系值（根据本章互动）+ 连锁反应计算
- write-chapter 写前注入当前关系状态（影响角色行为）
- 关系值影响剧情走向卡片的生成（高信任→合作选项，低信任→对抗选项）
- 引用计数追踪帮助识别被遗忘的角色/设定

## 操作

- `/relationships 查看` — 显示所有关系
- `/relationships [角色A] [角色B]` — 查看两人关系详情
- `/relationships 修改 [角色A] [角色B] [维度] [值]` — 手动调整

## NPC情绪历史追踪（v16 新增 · 移植自游戏NPC情绪AI）

**核心：NPC对主角的态度不只看当前数值，还看历史轨迹。**

在每条关系的 `history` 数组中，系统自动追踪互动轨迹。writer agent在写NPC反应时，参考history中的趋势而非只看当前值。

**情绪趋势判定：**
- 最近3次互动都是正面 → NPC态度"回暖"（即使绝对值还低，也应该比之前友善）
- 最近3次互动都是负面 → NPC态度"恶化"（即使绝对值不算低，也应该更冷淡）
- 正负交替 → NPC态度"矛盾"（可用于制造张力——信任却防备、讨厌却尊重）

**在build_manifest中注入：**
manifest.relationships_loaded中每条关系附带 `trend: warming|cooling|conflicted|stable`
