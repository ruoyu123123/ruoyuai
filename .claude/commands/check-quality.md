# 质量检查流程

## 第零步：Anti-Slop 机械扫描（不依赖LLM）

**在LLM评估之前，先执行机械扫描。** 参考 /anti-slop 规则库。

用 Bash 执行以下检测：

```bash
FILE="[待检查的章节文件]"

# 1. 禁用词检测
echo "=== 禁用词 ==="
grep -onE '顿时|紧锁|显然|似乎|此刻|淡淡|心中一凛|眼中闪过一丝|微微挑眉|仿佛|嘴角勾起一抹|深吸一口气|缓缓地说|沉吟片刻|不容置疑|波涛汹涌|与此同时|值得一提的是|不仅如此|事实上' "$FILE"

# 2. AI情绪/动作套话
echo "=== AI套话 ==="
grep -onE '心中一暖|心头一震|心中暗道|不由得|嘴角微微上扬|轻轻地|缓缓地|默默地|静静地|淡淡地|微微一笑|微微点头|微微皱眉' "$FILE"

# 3. 对话标签统计
echo "=== 对话标签 ==="
grep -oE '说道|笑道|怒道|叹道|喊道|问道' "$FILE" | sort | uniq -c | sort -rn

# 4. Show-Don't-Tell违规
echo "=== 直接情绪 ==="
grep -onE '感到愤怒|感到悲伤|感到高兴|感到恐惧|内心充满|心中涌起|一股.*涌上心头' "$FILE"

# 5. 总结性结尾
echo "=== 总结结尾 ==="
tail -5 "$FILE" | grep -E '这一刻.*明白了|从此以后|就这样.*结束了|一切都.*改变了'
```

### 第零步补充：语义层扫描（semantic_slop_scanner · v19 B+ 文笔语义层）

上面的 grep 是**机械层**，只抓「词」。但句级 AI 腔（把比喻嚼碎喂读者、金句体、
否定式排比、系动词回避、虚假范围、限定词叠用、强行三段列举、对话标签同义词循环）
正则抓不到——补跑**语义层**扫描器：

```bash
python core/scripts/semantic_slop_scanner.py "<项目路径>" <ch> --all
```

输出 8 个检测器的 JSON 报告，每条命中全部 `gate_level=advisory`——是「文笔建议」
不是「客观错误」，写作 agent 有充分理由可豁免（理由写进 `第N章_changes.json`
的 `self_eval.waivers`，< 100 字、具体到本章场景）。

> **注**：逐章流水线里本扫描器已由 `audit_hub.py` 作为第 7 个校验器统一调度，
> 无需单独跑；此处单列是为 `/check-quality` 被单独调用做质检的场景。机械层（grep）
> + 语义层（semantic_slop_scanner）两层互补，不重叠。

```bash
python core/scripts/plan_tracker.py step "$PLAN_ID" --n 1 --output "_数据库/.qa/第<ch>章_antislop.json"
```

**机械扫描结果直接影响最终评分：**
- 禁用词 ≥ 3个 → 自动扣 15 分
- 禁用词 1-2个 → 自动扣 5 分/个
- AI套话 ≥ 2个 → 自动扣 10 分
- "说道"出现 ≥ 5次 → 自动扣 5 分
- Show-Don't-Tell违规 ≥ 1个 → 自动扣 5 分/个

# 质量检查清单

## ✅ 核心指标

### 1. 开头是否足够劲爆？
- [ ] 前100字是否立刻抓住注意力？
- [ ] 是否痛点/冲突前置？
- [ ] 是否避免无意义铺垫？

### 2. 读者是否解气？
- [ ] 虐点是否足够密集？
- [ ] 爽点是否让人满足？
- [ ] 反转是否出人意料？

### 3. 主角状态是否形成有效"爽"点？
- [ ] 主角离开施虐环境后的状态？（更好/平静）
- [ ] 是否展现精神境界的提升？
- [ ] 是否避免单纯的物质/地位碾压？

### 4. 人物行为逻辑是否一致？
- [ ] 角色行为符合性格设定？
- [ ] 决策有合理动机？
- [ ] 信息差运用是否合理？

### 5. 节奏是否紧凑，重点突出？
- [ ] 无冗余情节？
- [ ] 高潮低谷分布合理？
- [ ] 每章都有明确的情节推进？

---

## ❌ 禁忌检查

### 旁白类禁忌
- [ ] 是否有"表面看起来...但实际上..."类表述？
- [ ] 是否有宏大空泛的概括性描述？
- [ ] 是否所有叙述都有具体依托？

### 对话类禁忌
- [ ] 对话是否口语化？
- [ ] 是否避免"从今天起""你已踏入"等非日常用语？
- [ ] 是否有人味和真实感？

### 环境描写禁忌
- [ ] 环境描写是否超过2-3句？
- [ ] 是否服务于情节而非单纯营造氛围？

### 心理活动禁忌
- [ ] 是否过度描写内心独白？
- [ ] 是否多用行动代替心理描写？

### 结尾禁忌
- [ ] 是否避免总结性结尾？
- [ ] 章节结尾是否用具体场景/动作收束？

---

## 📊 评分标准

**优秀（90-100分）**
- 所有核心指标全部达标
- 无任何禁忌违反
- 情节引人入胜，读者欲罢不能

**良好（75-89分）**
- 核心指标基本达标
- 偶有1-2处禁忌违反但不影响阅读
- 情节流畅，有亮点

**及格（60-74分）**
- 部分核心指标未达标
- 多处禁忌违反
- 情节平淡，需要改进

**不及格（60分以下）**
- 多数核心指标未达标
- 严重违反写作禁忌
- 建议重写

## 🔒 正典校验（Canon Check）

### 校验流程

1. **加载锁定事实**：
   - Read `_数据库/人物卡.json`，提取所有角色的 `locked_facts` 字段
   - Read `_数据库/世界观.json`，提取世界规则

2. **逐项比对**：
   - 扫描本章正文，检查是否有与 locked_facts 矛盾的描述
   - 检查项包括：
     - 角色外貌描述是否与锁定值一致
     - 角色持有物件是否正确
     - 地点/场景描述是否与世界观一致
     - 角色能力/技能是否与设定一致
     - 时间线是否合理（不能出现已死角色、未获得的物件等）

3. **问题分级**：
   - 🔴 CRITICAL：直接矛盾（蓝眼→棕眼）— 必须修正
   - 🟡 WARNING：可能矛盾（模糊描述可能被误读）— 建议修正
   - 🔵 INFO：新增事实（建议锁定）— 提示用户确认

4. **输出格式**：
```
🔒 正典校验结果：

🔴 CRITICAL (必须修正)：
  - 第3段：「李白棕色的眼睛」与锁定事实冲突（应为蓝色，第1章确立）

🟡 WARNING (建议修正)：
  - 第7段：王经理用右手递名片，但第3章暗示其右手有伤

🔵 INFO (建议锁定)：
  - 第5段：首次提到李白的剑鞘是黑色的 → 建议锁定
```

### 与质量评分的关系
- 存在 CRITICAL 级别问题时，质量评分自动扣 20 分
- 存在 WARNING 级别问题时，质量评分自动扣 5 分/条

## 🎨 风格一致性校验（Style Consistency Check）

### 校验流程

1. **加载风格基线**：
   - Read `_数据库/人物卡.json`，提取各角色的 `voice_pack.style_samples`
   - Read `_数据库/章纲摘要.json`，获取前3章的 `mood` 字段作为风格参考

2. **逐项比对**：
   - **角色对话风格**：检查每个角色的对话是否符合其 style_samples 的模式
     - 句子长度是否匹配 voice_pack.rhythm
     - 是否使用了 banned_phrases
     - 是否偏离了 style_samples 展示的说话方式
   - **叙事风格**：检查本章的叙事风格是否与前文一致
     - 对话比例是否偏离场景规则设定的 ±15%
     - 描写密度是否突变
     - 叙事视角是否一致

3. **问题分级**：
   - 🔴 DRIFT：严重风格漂移（角色说话方式完全变了）
   - 🟡 SHIFT：轻微偏移（可接受但需注意）
   - 🟢 CONSISTENT：风格一致

4. **输出格式**：
```
🎨 风格一致性结果：

🔴 DRIFT：
  - 王经理在第5段的对话过于温柔，与 style_samples 中的"简短有力"风格不符

🟡 SHIFT：
  - 本章对话比例 72%，高于场景规则设定的 50-70%（轻微偏高）

🟢 整体风格一致性：良好
```

### 与质量评分的关系
- 存在 DRIFT 级别问题时，质量评分自动扣 10 分
- 存在 SHIFT 级别问题时，不扣分但标记提醒

## 🔧 质量修复工作流

### 触发条件
当评分低于80分时，提示用户是否需要修正。

### 修复流程

1. **识别问题类型**：
   - 结构性（人物逻辑、节奏、情节推进）→ 标记为需重写段落
   - 表达性（对话、环境描写、心理活动）→ 标记为需润色段落
   - 一致性（角色行为漂移、设定冲突）→ 需对比人物卡/世界观修正

2. **确认修正**：
   - 用户说"修正"或"按建议改"时执行：
     a. 结构性问题 → 重写问题段落
     b. 表达性问题 → 逐段润色
     c. 一致性问题 → Read `_数据库/人物卡.json` 和 `_数据库/世界观.json` 对照修正
     d. 修正完成后执行 /save-state 更新状态

3. **修正模式**：
   - 快速模式（75-79分）：仅修正最严重的2-3处
   - 深度模式（60-74分）：修正所有标记问题
   - 重写模式（<60分）：建议重新执行 /write-chapter

---

**检查目的：确保每一章都能让读者"停不下来"**

## 🗡️ 对抗式编辑（Adversarial Editing）

当评分 < 85 分时，自动执行对抗式编辑分析：

### 执行流程

1. **删减分析** — 假设必须删掉500字，哪些段落最该删？
   - 标记每段的"信息密度"（推进剧情/塑造角色/营造氛围/纯填充）
   - "纯填充"段落 = 删除候选
   - 输出删减建议列表

2. **分类** — 将删减候选分为：
   - 🗑️ 可直接删除（不影响剧情理解）
   - ✂️ 可压缩（保留核心信息，缩短表达）
   - 🔄 可替换（用更有力的表达替代）

3. **对比输出** — 给出修改前后对比：
   ```
   ❌ 原文（42字）：
   "王经理缓缓地站起身来，深吸一口气，目光中闪过一丝复杂的情绪，然后沉吟片刻才开口说道。"
   
   ✅ 改后（18字）：
   "王经理站起来，盯着他。'说。'"
   ```

4. **再评估** — 删减/替换后重新评分，确认改进

### 对抗式编辑原则
- 每次删减后问：读者会注意到少了什么吗？如果不会 → 删
- 优先删除：环境描写 > 心理活动 > 过渡段 > 对话
- 保护：冲突推进、角色塑造、伏笔埋设
