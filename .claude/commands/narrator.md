# 叙事导演系统

## 设计哲学

借鉴 RimWorld 的 AI Storyteller：
- 不是随机生成事件，而是根据"叙事节奏"智能调控
- 保证故事有"呼吸感"——高潮后必须有缓冲，平静后必须有冲突
- 根据用户选择的叙事模式，调整事件密度

## 叙事模式（用户可选）

| 模式 | 灵感来源 | 特征 |
|------|----------|------|
| 模式 | 灵感来源 | 平均事件强度 | 强度波动率 | 高潮间最小间距 | 特征 |
|------|----------|-------------|-----------|---------------|------|
| 🔥 紧张模式 | Cassandra | 0.70 | 0.20 | 1章 | 事件密集，难度递增，几乎没有喘息 |
| ⚖️ 平衡模式 | 默认 | 0.50 | 0.35 | 3章 | 高潮→缓冲→高潮，经典三幕结构 |
| 🌊 波浪模式 | Randy Random | 0.45 | 0.50 | 0章 | 不可预测，可能连续高潮也可能长期平静 |
| 🌿 慢热模式 | Phoebe Chillax | 0.35 | 0.15 | 5章 | 大量日常铺垫，高潮少但爆发力强 |

**量化参数说明（v16·移植自AI_NovelGenerator叙事导演）：**
- **平均事件强度**：0-1，本模式下章节事件的平均强度
- **强度波动率**：0-1，越高越不可预测（波浪模式0.5=高度随机）
- **高潮间最小间距**：两个高强度章（≥0.7）之间至少隔几章
- 叙事导演根据前3章emotion_value + 当前模式参数，计算本章推荐强度
- 推荐强度 = clamp(均值 + random(-波动, +波动), 0, 1)，但必须满足最小间距

### 自适应难度曲线（v16 新增 · 移植自RimWorld Cassandra算法）

**核心：事件强度不是固定的，而是根据"故事财富"动态调节。**

RimWorld的Cassandra根据殖民地财富+人口动态调整事件难度。我们的等价物：

| 故事指标 | 等价含义 | 影响 |
|---|---|---|
| 已完成章数 | 类似"殖民地年龄" | 章数越多→可用更大事件 |
| 未回收伏笔数 | 类似"殖民地财富" | 积压越多→越需要释放 |
| 前3章emotion均值 | 类似"最近事件历史" | 连续低谷→该拉升了 |
| 活跃角色数 | 类似"殖民者数量" | 角色越多→群戏机会越大 |
| 威胁时钟进度 | 类似"袭击倒计时" | 快满→强制高强度事件 |

**自适应公式：**
```
base = 模式平均强度
adjustment = 0
if 前3章emotion均值 < -3: adjustment += 0.15  # 连续低谷→拉升
if 前3章emotion均值 > +5: adjustment -= 0.10  # 连续高峰→缓一缓
if 未回收Tier1伏笔 >= 3: adjustment += 0.20  # 积压伏笔→催促释放
if 威胁时钟最近 filled >= segments-1: adjustment += 0.25  # 时钟快满→强制高潮

recommended = clamp(base + adjustment + random(-波动, +波动), 0, 1)
```

**这让叙事导演从"固定配方"升级为"响应式AI"——像RimWorld一样根据故事状态动态调节节奏。**

## 叙事导演的职责

每章写前，叙事导演根据以下因素决定"本章应该发生什么级别的事件"：

### 输入
- 前3章的情绪值（从故事块摘要.json）
- 当前叙事模式
- 未触发的事件池（从事件表.json）
- NPC 计划进度
- 伏笔到期情况
- 用户上一次的走向选择

### 输出：本章事件强度指令
```
📊 叙事导演指令（第N章）：

模式：⚖️ 平衡
前3章情绪：[7, 3, -2] → 连续下降，本章需要拉升
事件强度：★★★★☆（高强度章节）
建议事件类型：转折/揭露/对抗
NPC 计划状态：王经理的调查计划进度 80%，即将触发
伏笔压力：2个伏笔即将到期
导演建议：本章适合引爆一个大事件，打破当前的下降趋势
```

## NPC 计划系统（借鉴 CK3 Scheme）

### 计划数据结构

存储在 `_数据库/人物卡.json` 的 offscreen 字段中，升级为：

```json
"schemes": [
  {
    "id": "调查主角",
    "type": "调查/暗杀/拉拢/陷害/保护",
    "initiator": "王经理",
    "target": "主角",
    "progress": 75,
    "success_rate": 60,
    "participants": ["前台小张（被迫配合）"],
    "risk": 30,
    "started_ch": 2,
    "estimated_trigger_ch": 6,
    "discovery_chance_per_ch": 15,
    "status": "进行中",
    "milestones": [
      {"progress": 25, "event": "开始收集信息", "ch": 2},
      {"progress": 50, "event": "发现简历疑点", "ch": 4},
      {"progress": 75, "event": "获得关键证据", "ch": 5}
    ]
  }
]
```

### 计划推进规则

每章 save-state 时：
1. 所有进行中的计划 progress += 10~20（根据参与者能力）
2. 检查是否达到 milestone → 触发对应事件
3. 检查 discovery_chance → 是否被主角发现
4. progress >= 100 → 根据 success_rate 判定结果

### 计划对剧情的影响

- 计划进度 > 50%：NPC 行为开始出现"异常"（可被主角察觉）
- 计划进度 > 80%：紧迫感增加，叙事导演提升事件强度
- 计划触发：产生重大剧情转折

## 涌现规则引擎（借鉴 Dwarf Fortress）

### 核心原则

> 不写剧本，只写规则。故事从规则的交互中自然涌现。

### 连锁规则

```json
{
  "chain_rules": [
    {
      "trigger": "角色A的信任度对角色B降到-50以下",
      "consequence": "角色A开始策划针对角色B的计划",
      "auto_create_scheme": true
    },
    {
      "trigger": "某角色的恐惧值超过80",
      "consequence": "该角色可能叛变或逃跑",
      "probability": 0.3
    },
    {
      "trigger": "两个角色的好感度同时超过70",
      "consequence": "可能形成联盟",
      "probability": 0.5
    },
    {
      "trigger": "某角色连续3章处于负面情绪",
      "consequence": "该角色性格可能发生转变",
      "probability": 0.4
    }
  ]
}
```

### 涌现叙事链示例

```
规则1：王经理调查主角 → 发现简历造假
规则2：发现造假 → 信任度暴跌
规则3：信任度暴跌 → 开始策划"揭露计划"
规则4：揭露计划进度100% → 当众质问
规则5：当众质问 → 主角被迫回应（剧情走向卡片）
规则6：如果主角选择"坦白" → 关系可能修复
规则7：如果主角选择"反击" → 冲突升级，新的连锁开始
```

## 写作集成

- **write-chapter 写前**：叙事导演生成本章事件强度指令
- **save-state 写后**：推进所有 NPC 计划，检查连锁规则
- **剧情走向卡片**：叙事导演影响卡片的"紧迫程度"

## 操作

- `/narrator 状态` — 显示当前叙事导演的判断
- `/narrator 模式 [紧张/平衡/波浪/慢热]` — 切换叙事模式
- `/narrator 计划` — 显示所有 NPC 的进行中计划
- `/narrator 连锁` — 显示当前可能触发的连锁规则
