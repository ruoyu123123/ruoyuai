## 一、节奏 / 风格工艺规律（诡秘冷峻风专属盲区）

### N1 ⚠️ 冷峻短句风会系统性把段落写碎 —— 必须配段长下限
- **现象**：单句成段率连续 8 章超标（chX: 82.7%, 上限 80%）；段落均长连续 5 章低于下限（11.4 字，目标 14-30）；极短段占比连续 3 章超 30%（36.4%）。三个指标同源同向。
- **为什么**：诡秘/克苏鲁冷峻风鼓励「一句一顿」营造压抑感，writer 把短段当作风格安全捷径无限放大，跟破折号/代词过用是**同一类元-anti-slop 结构层重犯**（参见 memory `feedback_meta_anti_slop_structure_blindspot_recurrence`）。单章扫描看不出，跨 5+ 章才暴露趋势。
- **怎么用**：冷峻风项目开写前，在 voice_pack/anchor 里把「单句成段率 ≤80% + 段落均长 14-30 字 + 极短段 ≤30%」写成**硬上限**（不是建议），并让跨章 scanner 在第 3 章起就盯趋势。冷峻 ≠ 全篇碎句，气氛靠节奏对比（长句铺垫 + 短句爆破），不是靠均匀的碎。

### N2 ⚠️ Kishōtenketsu「转」段缺失是单人氛围章的固定病
- **现象**：PLOT_kishotenketsu 在第 7/8/9/15 章复发 4 次，样本全是「单人氛围章后半部缺『转』段标记」。
- **为什么**：单主角、无对手戏的氛围章（独自调查/独处推理）没有外部冲突推动，writer 容易写成「平铺直叙的观察流」，缺认知反转。这是**章型相关**盲区——群戏章不犯，单人章必犯。
- **怎么用**：识别为「单人氛围章」时，brief 强制要求后半部至少一个「转」：认知反转（才/原来/竟/没想到）或时间转折（突然/忽然/这时/蓦地）。把它做成单人章型的 checklist 项，不靠 writer 自觉。

### N3 💡 info-dump 在世界观重的题材后期反弹
- **现象**：NARRATIVE_info_dump 第 8/15/16 章复发（早期不犯，中后期犯）。
- **为什么**：隐秘组织/序列体系类设定密集，前期靠悬念压着不解释，到中后期「该还债了」时 writer 倾向一次性长叙述补设定。
- **怎么用**：设定揭密章把「一段长解释」拆成「对话盘问 + 物件触发 + 分次释放」，后置到真正需要的时刻。世界观越重的题材，越要在大纲层预排揭密节奏，别攒到一章爆。

### N4 💡 长台词独白是开篇章的高发区
- **现象**：LONG_MONOLOGUE 在第 1/2/3/4 章密集复发 6 次（开篇 4 章占 4 次），中段消退后第 12/14 章反弹。
- **为什么**：开篇要快速立人设/交代背景，writer 用长独白当信息投喂捷径；中段揭密章反弹同理。
- **怎么用**：开篇 4 章 + 揭密章把 >80 字独白列为重点规避项。信息投喂改用「他人提问打断 + 行动中带出」。

## 二、伏笔 / 结构工艺规律

### F1 ⚠️ 第三人称限知 + offscreen 配角 → CHARACTER_MISSING 误报，需提前声明
- **现象**：大纲出场角色在正文未出现被判 CHARACTER_MISSING（第 2 章触发、第 14 章靠豁免理由「限知锚角色，配角仅 offscreen/背影」解决）。
- **为什么**：严格第三人称限知视角下，配角合理地只以 offscreen/背影存在，但大纲层「出场角色」字段不区分「实际登场」和「被提及」，scanner 据此误报。
- **怎么用**：限知 POV 项目，大纲角色字段拆「on-screen / offscreen-only」两类；offscreen 配角在 changes.json 预写豁免理由，别等 scanner 报了再补。这是 POV 选型的连带成本，选限知就要配套。

### F2 💡 段间人称切换是限知视角的隐性破口
- **现象**：NARRATIVE_perspective_shift 第 7/11/13 章复发（first ↔ third 段间切换）。
- **为什么**：第三人称限知章里插入主角内心独白时，writer 不自觉滑进第一人称口吻，造成段间人称漂移。
- **怎么用**：限知章 writer step 0 锚定「全章人称单一」，内心活动用自由间接引语（第三人称转述心理）而非切第一人称。novel-voice-checker 跨章查人称一致性。

### F3 💡 MRU（动作-反应单元）顺序错位是高频低危项
- **现象**：NARRATIVE_mru 跨 7 章复发但每次仅「1 处错位」，低密度长尾。
- **为什么**：刺激→反应的微观顺序（先写反应后写刺激）是 writer 的肌肉记忆错误，零星出现不致命但持续存在。
- **怎么用**：作为 writer 自查项而非门禁。每章扫 1 处属正常噪声，不值得为单处返工；只在某章突增（≥3 处）时干预。

## 三、特殊设定的叙事处理（多身体/同步类金手指）

### S1 ⚠️ 「多分身记忆同步」类金手指的叙事最大坑是 POV 与信息边界
- **现象**：本项目金手指=「≤7 分身、独立行动、统一记忆/能力同步」，全 16 章 NARRATIVE_pov 被豁免 16 次（每章都触发），豁免理由统一为「third_person_limited 严守」。
- **为什么**：多分身同步本质上诱使叙事在多个分身视角间跳，scanner 持续报 POV 异常；但作者刻意用「单一限知锚 + 同步信息延迟」处理，每章都得豁免。这不是 bug，是该类设定的**固定叙事张力**。
- **怎么用**：写「多身体/分身/集体意识/记忆共享」类金手指时，开写前定死两条规则并写进 anchor：①叙事 POV 锁单一主体（哪怕能力上多线并行），②分身间信息同步设「感知延迟/带宽限制」制造悬念，否则金手指消解一切冲突。预期 POV scanner 会全程报警，提前在 changes.json 模板预置豁免理由，别每章手忙。

### S2 💡 同步类金手指要给「位置感/身份感丧失」配代价时钟
- **现象**：本项目时钟表含「位置感丧失」clock（多身体并行的副作用代价）。
- **为什么**：无代价的多线并行 = 无张力。把「分身越多，主体性越稀释」做成显性倒计时，金手指才有戏剧重量。
- **怎么用**：任何「能力线性增长型」金手指都配一个反向消耗 clock（位置感/人性/记忆完整性/寿命），narrator 据此调压。

## 四、ECAS（事件簇）模式经验

### E1 ⚠️ ECAS 簇模式下字数仍会系统性偏低 —— cluster 边界要复核
- **现象**：STYLE_章节字数在第 2/8/14 章复发偏低（2287 vs 目标 2800-5200，缺 ~700 字），WC_TOO_SHORT 第 2/14 章触发。
- **为什么**：ECAS 把多章并簇写，splitter 切自然截断点时，簇尾章容易分到字数不足的尾料；这与 memory `feedback_ecas_word_count_5_layer_break` 同根（字单位三义 + researcher→planner 放大 + writer reward hacking + checkpoint 静默通过）。
- **怎么用**：ECAS 项目在 splitter 后必做「每章字数 ≥下限」兜底校验，簇尾章是高危位；checkpoint 必须 fail-loud，不静默放行。参见已沉淀的 ECAS 5 层修复，本项目复现验证了该规律真实存在。

### E2 💡 ECAS 转向时极易漏带 v17.7 调研先行规则
- **现象**：本项目用 cluster_001~005 draft 模式（事件簇.json + 事件簇.json.broken_backup 显示有损坏修复历史）。
- **为什么**：架构升级（逐章→簇）时现存硬约束（调研先行/字数/POV）不会自动迁移到新流程的真正阻断点，与 memory `feedback_ecas_research_first_4_layer_enforce` 同模式。
- **怎么用**：任何写作流程架构升级，必须把现存所有硬约束逐条迁到新流程的 hook/schema/plan step/manifest 4 个真正阻断点，不能假设「规则还在文档里就有效」。事件簇 JSON 出现 .broken_backup = 引擎类脚本写盘需 --dry-run 防污染 baseline（参见 `feedback_v20_1_world_evolution`）。

## 五、检测器校准经验（顾问制实战验证）

### C1 ⚠️ 风格类检测器在「强风格基线」项目会被全程豁免 —— 这是顾问制正常工作，不是失败
- **现象**：12 个检测项被全 16 章豁免（STYLE_对话占比/方括号设定/逗句比 各 16 次，NARRATIVE_pov/PLOT_beat/PLOT_knowledge 各 16 次等），learning_loop 全部产出「建议放宽阈值」校准建议。
- **为什么**：项目刻意复刻《BookC》冷峻低对话风，与通用 scanner 默认阈值（按主流网文调）系统性冲突。豁免理由全部具体（「诡秘风开篇禁堆设定」「陈默 voice 慢半拍」），属合理 advisory 豁免——v19 顾问制设计如此。
- **怎么用**：强风格基线项目（蒸馏特定作者风），开写前用 `validate_style` 的风格 profile 覆盖默认阈值，**别让 writer 每章手动豁免 12 项**（16 章 ×12 项 = 192 次豁免噪声，污染 learning_loop 信号）。蒸馏出风格 skill 时应同步产出「该风格的 scanner 阈值覆盖表」，注入 audit_hub。这是蒸馏→检测链路的缺失环节。

### C2 💡 全章 100% 豁免 + 不集中单一章型 = 阈值问题而非写作问题
- **现象**：learning_loop 对 16/16 全豁免项产出 confidence 0.75 的「adjust_threshold」建议，明确标注「不集中于单一章节类型」。
- **为什么**：若问题集中某章型 = 写作问题（需修文）；若均匀分布全章型 = 检测器与本项目风格不匹配（需调阈值）。这是「工具校准 vs 写作修复」的判别信号。
- **怎么用**：复盘豁免数据时，先看分布：集中 → 改写作约束；均匀全覆盖 → 改检测器阈值/降 severity。别把阈值问题当写作问题反复骚扰 writer（learning_loop §统计反复豁免本意如此）。

## 七、本次 distill 元结论

- **最高价值新规律**：C1（强风格项目应在蒸馏阶段产出 scanner 阈值覆盖表，而非靠 writer 每章手动豁免 192 次）—— 这是蒸馏→检测链路的真实缺失环节，scanner/memory 均未覆盖。
- **次高**：S1/S2（多分身同步类金手指的 POV 锁定 + 反向代价 clock）—— 设定类型化经验，可复用到任何「能力并行增长」金手指。
- **第三**：N1（冷峻短句风的段长三联指标同源，需开写前设硬上限）—— 元-anti-slop 模式的新具体维度（碎段），补全「结构层套路 N 维清单」。
