## 💡 经验总结

### 成功经验
1. **工具先行**: 先建 `log_util.py` 统一接口，再逐个重构
2. **自动检测**: `check_logging_standard.py` 快速定位违规
3. **优先级**: 核心流水线优先（orchestrator 是 AI 驱动入口）
4. **渐进式**: 不求一次全改，先改关键路径

### 遇到的坑
1. **Windows 编码**: emoji/中文需 UTF-8 包装 stdout
2. **字符串匹配**: Edit 工具对多行字符串匹配敏感
3. **豁免白名单**: CLI 工具（plan_tracker）需保留 print

### 设计决策
- **SILENT 默认**: orchestrator 程序驱动模式静默，只输出结构化 JSON
- **DEBUG 门控**: 开发调试信息需显式开启（避免污染生产日志）
- **logger 实例**: 每个模块独立 logger（便于追踪来源）

## 📝 附录

### A. 日志级别详解

| 级别 | 用途 | 输出目标 | 示例 |
|------|------|----------|------|
| SILENT | 程序驱动 | 仅结构化 JSON | `{"status": "ok"}` |
| INFO | 关键进度 | stdout | `[INFO] ▶ step 1: 生成正文` |
| DEBUG | 开发调试 | stdout | `[DEBUG] [step1] $ gen_writer.py ...` |
| ERROR | 异常错误 | stderr | `[ERROR] 脚本异常: FileNotFoundError` |

### B. 环境变量

```bash
# 设置日志级别
export RUOYU_LOG_LEVEL=INFO    # 默认
export RUOYU_LOG_LEVEL=DEBUG   # 调试模式
export RUOYU_LOG_LEVEL=SILENT  # 静默模式

# 开启调试（优先级高于 LOG_LEVEL）
export RUOYU_DEBUG=1
```

### C. 迁移规则

```python
# 旧代码
print(f"[OK] 完成第 {n} 步")
print(f"[ERROR] 失败: {e}", file=sys.stderr)
print(json.dumps(result, ensure_ascii=False))

# 新代码
from log_util import get_logger, print_result_json
logger = get_logger(__name__)

logger.info(f"完成第 {n} 步")
logger.error(f"失败: {e}")
print_result_json(result)
```
